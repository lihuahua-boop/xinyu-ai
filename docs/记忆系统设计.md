# 记忆系统设计

这是产品的护城河，也是 V1.0 方案里写得最轻、但工程量最重的一块。
真正的难点不是"存"，而是**什么时候写、写什么、什么时候想起来、怎么用自然的方式说出来**。

## 一、四类记忆（对应产品方案第六章）

| 类别 | 内容 | 例子 | 默认重要度 |
| --- | --- | --- | --- |
| basic 基础信息 | 生日、职业、城市、名字 | 用户在 3 月 14 日生日 | 0.6-0.85 |
| preference 偏好记忆 | 喜欢 / 不喜欢 / 沟通期待 | 不喜欢被冷处理 | 0.65-0.9 |
| emotion 情绪记忆 | 重要经历、难过的时期、开心的事 | 因为工作压力失眠过 | 0.55-0.9 |
| relationship 关系记忆 | 第一次聊天、关系升级、纪念日 | 第一次聊天在 9 月 14 日 | 0.8 |

## 二、写入策略

1. **只记用户明确说过的**。规则抽取（`memory/extractor.py`）优先，模型不参与编造；
2. **抽取维度**：生日 / 名字 / 职业 / 城市 / 喜欢 / 不喜欢 / 宠物 /
   对陪伴方式的期待 / 压力事件 / 用户明确要求记住的事；
3. **重要度** = 类别基础值 + 情绪强度加成 + 显式强调词加成（永远 / 特别重要 / 记住）；
4. **去重合并**：同类别 + 同 key 视为同一条；文本包含关系（如"喜欢猫" ⊂ "喜欢猫，家里有一只猫叫团子"）自动合并，
   保留更完整的表述，重要度取高；
5. **软删除**：用户可以随时让他忘掉某件事（`DELETE /api/memories/{id}`），
   这既是产品体验也是合规要求。

## 三、召回策略

混合打分（`memory/retriever.py`）：

```
score = 0.42 * 字面相关度
      + 0.26 * 重要度
      + 0.18 * 时间衰减
      + 0.14 * 新鲜度
      + 类别加成
```

- **字面相关度**：中文二字组 + 英文词，带 idf 权重，避免"的、了、我"这类高频噪声；
- **时间衰减**：半衰期默认 45 天，久远的事权重下降但不归零；
- **新鲜度**：刚提过的记忆降权（12 小时内再乘 0.45），避免 AI 反复念叨同一件事；
- **类别加成**：问题里出现"喜欢""难过""我们"这类信号时，对应类别加权。

用户在考记忆（"你还记得吗"）时会放宽阈值，优先想起重要的事——这正是"被记住"的高光时刻。

接入向量检索时，只需要把"字面相关度"换成余弦相似度，
其余权重与降权逻辑保持不变（`search_by_embedding` 已留好位置）。

## 四、注入策略

分层组装，控制在 token 预算内（默认 900 token）：

1. 常驻画像（基础信息，每轮都带，不占召回额度）
2. 召回片段（按分数排序，超预算按重要度裁剪）
3. 说话约束（"自然地用，不要生硬复述"）

模型侧还有一层约束：不虚构用户没说过的事；不确定时用"好像""我记得你说过"留余地。

## 五、可解释性

每条被用到的记忆都会返回给前端（`memories_used`），并附带一句理由：

- "和这次聊到的事直接相关"
- "这是你特别在意的，他一直记着"
- "这件心事他记了很久"

界面上会显示"他想起：…"的小卡片。
用户能看见 AI 为什么这么说，信任才建立得起来——这也是留存的关键。

## 六、评测建议（上线前必做）

1. 建 100 条真实对话的标注集，标注"这一轮应该想起哪几条记忆"；
2. 指标：召回率、误召回率、重复提及率、用户感知率；
3. 用户感知率最重要——用埋点统计"记忆回响出现后用户继续回复的比例"；
4. 每周回放 badcase，调整权重与抽取规则。
