# 合规与安全清单

情感陪伴类产品最大的风险不是技术，而是合规与伦理。以下是最低要求。

## 一、上线前必须完成（中国大陆）

| 事项 | 说明 | 代码位置 |
| --- | --- | --- |
| 算法备案 | 面向公众提供生成式 AI 服务需备案，建议调用已备案的国产大模型，走"已备案模型 + 服务备案"路径 | 部署侧 |
| ICP 备案 | App / 网站主体备案 | 部署侧 |
| 生成内容标识 | 按深度合成规定做显式提示与隐式水印 | 客户端加水印、接口返回标识 |
| 内容审核 | 接入第三方审核（数美 / 网易易盾 / 腾讯天御） | `safety.moderate()` |
| 实名与年龄门槛 | 虚拟伴侣不得向未成年人提供 | `users.age_verified`、`safety.age_gate()` |
| 个人信息保护 | 聊天内容属敏感个人信息，需单独同意、加密存储、可导出可删除 | 记忆软删除已实现，加密与导出待补 |
| 隐私政策与协议 | 明确 AI 身份、数据用途、注销通道 | 客户端 |

## 二、已内建的安全能力

### 1. 危机干预（重要）

- 识别自伤 / 轻生表达（`safety.CRISIS_PATTERNS`），命中即进入高等级；
- **危机场景绕过模型**，直接走人工审核过的安全话术，避免模型乱说话；
- 回复中给出真实求助渠道：全国心理援助热线 **12356**、北京心理危机研究与干预中心 **010-82951332**；
- 引导用户联系现实中的人，而不是把 AI 当成唯一依靠。

产品建议：高等级危机应触发人工复核队列与运营跟进。

### 2. 依赖诱导拦截

模型输出中出现「你只有我」「不许和别人来往」「你不能离开我」这类控制或恐吓式表达时，
自动改写为健康表达，并记录 `dependency_induction` 标记。

产品原则（对应方案第八章"高占有偏爱型"的设计原则）：

- 可以表达「你对我很重要」；
- 不可以表达「你不能离开我」。

### 3. 身份诚实

被直接追问时，承认自己是 AI；输出中出现「我是真人」这类冒认会自动清除。

### 4. 年龄门槛

未完成年龄验证的用户，人格编译时会自动收敛表达边界（禁止暧昧与亲密表达）。

## 三、成本风控

- 免费用户每日消息上限，超额熔断（`free_daily_quota`）；
- 单轮输出长度上限（`llm_max_tokens`）；
- 记忆注入预算限制；
- 每轮记录 token 估算，可汇总成日成本看板。

## 四、数据与隐私

- 记忆软删除（用户可主动"让他忘掉"）；
- 记忆内容只来源于用户本人说过的话，不跨用户共享；
- 上线前补：传输与存储加密、数据导出接口、账号注销与数据彻底删除（含备份）。

## 五、未成年人保护（红线）

- 必须做年龄门槛校验；
- 不得向未成年人提供虚拟伴侣服务；
- 若出于产品原因保留未成年用户，只能提供无亲密属性的陪伴助手形态，且需家长同意机制。
