# 架构设计

## 一、整体分层

```
网页客户端 / 未来的 Flutter App
              ↓  HTTP + JSON
        FastAPI 路由层（routers/）
              ↓
        对话编排 engine.py
   ↓        ↓        ↓        ↓
人格编译   记忆系统   情绪识别   安全护栏
persona   memory    emotion   safety
   ↓        ↓        ↓        ↓
        模型适配层 llm/（mock | openai 兼容）
              ↓
        SQLite（users / characters / messages /
                memories / milestones / proactive_messages）
```

关键点：**业务能力不写在提示词里，而是写在代码里**。
人格、记忆、关系、安全都各自是独立模块，模型只是最后一步的"说话者"。
这样换模型、换供应商都不影响产品能力。

## 二、一轮对话的完整链路（engine.chat）

1. 校验：角色归属、空消息、长度、免费额度
2. 内容审核钩子（safety.moderate，默认放行，上线接三方）
3. 安全判定：危机 / 低落观察
4. 情绪识别：词典 + 强度 + 需求（安慰 / 求建议 / 倾诉 / 考记忆 / 问身份）
5. 记忆召回：混合打分取 top-k，并打召回点
6. 组装提示词：人格层 + 关系层 + 画像层 + 记忆层 + 情绪层（带 token 预算）
7. 生成：危机场景绕过模型走安全通道；模型异常自动降级到本地引擎
8. 输出审核：拦截依赖诱导与冒认真人
9. 落库：用户消息 + 回复消息（带情绪、用到的记忆、用量）
10. 写记忆：规则抽取写入（去重合并），更新结构化画像
11. 关系成长：算增量 → 每日上限 → 阶段迁移 → 记里程碑

每一步都有降级路径，任何一环失败都不会让用户看到空白回复。

## 三、模型适配层

统一接口 `ChatProvider`：

- `MockProvider`：本地情感回复引擎。零成本、离线可用，用于开发、演示与故障降级；
- `OpenAICompatProvider`：任何 OpenAI 兼容接口（DeepSeek / 通义 / 豆包 / Moonshot / 智谱 / OpenAI）。

切换只改环境变量，业务代码不动：

```
XINYU_LLM_PROVIDER=openai_compat
XINYU_LLM_BASE_URL=https://api.deepseek.com/v1
XINYU_LLM_API_KEY=sk-xxxx
XINYU_LLM_MODEL=deepseek-chat
```

未配置 Key 时自动退回本地引擎，服务不会因为缺配置而挂掉。

## 四、存储

MVP 使用 SQLite 单文件，接口统一收敛在 `db.py` 的 `query_all / query_one / execute`，
换成 PostgreSQL 只需要替换这一个文件。

上线前的迁移清单：

- 主库换 PostgreSQL，消息表按 `character_id` + 时间分区
- 记忆表增加向量列（pgvector），接 embedding 服务
- 对象存储放图片与语音，CDN 加速
- Redis 做配额计数、限流与主动陪伴调度

## 五、限额与成本控制

- 免费用户每日消息上限（默认 60 条），超额直接熔断并给出友好话术
- 单轮 `max_tokens` 上限（默认 600）
- 记忆注入预算（默认 900 token），超出按重要度裁剪
- 每次对话记录 `prompt_tokens_est / completion_tokens_est`，可直接汇总成成本报表

## 六、客户端

`web/` 是移动端优先的网页客户端，零构建步骤、零依赖，方便快速验证。

迁移到 Flutter 时的对应关系：

| 网页 | Flutter |
| --- | --- |
| 创建向导 4 步 | 4 个页面 + Provider 状态 |
| 聊天页 | ListView + SSE 流式接收 |
| 记忆页 | 分组列表 + 滑动删除 |
| 人格页 | Slider 组件（参数来自 `/api/meta/persona-params`） |

API 已经按前端的需要设计好，客户端不需要自己拼逻辑。
